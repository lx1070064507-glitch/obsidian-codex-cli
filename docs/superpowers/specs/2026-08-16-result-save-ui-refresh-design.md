# 成果保存一致性与侧边栏刷新优化设计

日期：2026-08-16  
状态：待实施

## 1. 目标

- 成果文件已经创建但关联笔记链接写入失败时，准确告知用户成果仍然存在，避免用户重试后生成重复成果。
- 减少聊天侧边栏空闲轮询、成果目录重复扫描和输入过程中的无关渲染。

## 2. 成果保存语义

保存前先读取关联笔记。关联笔记不存在或不可读时直接失败，不创建成果文件。

关联笔记预检通过后创建成果文件，再向关联笔记追加链接。保存操作返回成果及链接状态：

- 成果和链接均写入成功：显示“成果已保存”。
- 成果已写入、链接写入失败：保留成果，关闭保存弹窗，并显示包含成果路径的警告。该情况视为部分成功，不向界面抛出普通保存失败，避免用户重试。

不增加自动删除或回滚行为。

## 3. 侧边栏刷新策略

- 空闲状态不执行 200ms 定时刷新。
- Codex 回合运行期间保留 200ms 定时刷新，用于展示流式回复。
- 流式定时刷新只更新状态和消息，不扫描成果目录。
- 新建、恢复、发送完成、保存成果和提交成果等显式操作仍执行完整刷新。
- 输入框内容变化只重新计算发送按钮状态，不刷新消息或成果列表。

本次不引入控制器事件总线，也不重构现有模块关系。

## 4. 接口调整

成果存储返回值由单个 `ResultNote` 调整为包含以下信息的结果：

- 已创建的 `ResultNote`。
- 关联链接是否写入成功。
- 链接失败时用于界面展示的错误信息。

控制器和插件入口透传该结果，插件入口根据链接状态显示成功或部分成功提示。

聊天视图的刷新方法增加是否刷新成果列表的内部选项。定时流式刷新关闭成果刷新，显式操作保持默认完整刷新。

## 5. 测试

新增或调整自动化测试，覆盖：

- 关联笔记预检失败时不创建成果。
- 成果创建成功但链接写入失败时返回部分成功，成果文件继续存在。
- 控制器透传成果保存结果。
- 空闲状态下定时器不触发刷新。
- 流式定时刷新不读取成果列表。
- 输入内容变化不触发全量刷新，只更新发送按钮状态。

## 6. 非目标

- 不改变成果文件格式、路径规则或 Git 提交流程。
- 不增加成果自动删除、后台重试或事务日志。
- 不改用完整的事件驱动 UI 架构。
