# 文件树右键管理写入白名单设计

## 目标

在 Obsidian 左侧文件树的原生右键菜单中，为文件和文件夹提供写入白名单管理入口。操作后沿用现有白名单校验、保存和绿色高亮刷新流程。

## 菜单状态

右键目标分为三种状态：

1. 未被授权：显示“添加到写入白名单”，点击后添加目标的绝对路径。
2. 精确授权：目标绝对路径已直接记录在 `writablePaths` 中，显示“移出写入白名单”，点击后删除该条记录。
3. 继承授权：目标未被直接记录，但位于某个已授权目录内，显示“已由上级目录加入白名单”，菜单项禁用。

继承授权不提供移出操作。本功能不引入子路径排除规则，避免用户移除子项后仍被父目录授权却误以为权限已撤销。

## 技术设计

插件通过 Obsidian 官方 `workspace` 的 `file-menu` 事件注册菜单项，同时支持 `TFile` 和 `TFolder`。

事件目标的 Vault 相对路径通过 `FileSystemAdapter.getFullPath()` 转换为绝对路径。菜单状态判断使用 Windows 路径规范化和不区分大小写的比较规则，并区分精确匹配与上级目录包含关系。

添加时，将目标绝对路径追加到当前 `writablePaths`；移出时，只删除规范化后与目标精确匹配的记录。两种操作均调用现有 `updateSettings()`，由 `WorkspacePolicy` 统一完成路径存在性、类型、工作区归属和去重校验。成功保存后，现有 `WritablePathHighlighter.refresh()` 会更新文件树绿色字色，Codex 运行时也会按现有流程重建权限配置。

## 反馈与异常

- 添加成功：显示“已添加到写入白名单”。
- 移出成功：显示“已移出写入白名单”。
- 校验或保存失败：保留原设置并用 `Notice` 显示具体错误。
- 继承授权菜单项禁用，不触发设置写入。

## 代码边界

- 在独立服务中实现菜单状态和白名单数组变更的纯逻辑，便于测试。
- 在插件入口中注册 `file-menu` 事件、解析绝对路径并调用设置更新。
- 不修改现有设置页交互，不引入排除列表，不更改工作区根目录。

## 测试与验收

单元测试覆盖：

- 未授权路径返回“添加”状态。
- 精确授权路径返回“移出”状态。
- 父目录授权的子文件和子目录返回禁用的继承状态。
- Windows 路径大小写和分隔符差异不影响判断。
- 添加不产生重复项，移出只删除精确目标，不删除其他授权项。
- 菜单操作复用设置更新入口，失败时展示错误且不产生未处理的 Promise 拒绝。

构建验收包括 TypeScript 类型检查、完整测试和生产构建。手工验收在 Obsidian 文件树中分别验证文件、文件夹、精确授权项和继承授权子项的菜单文字、可用状态及绿色高亮变化。
