# Obsidian Codex CLI 多工作区与写入白名单设计

日期：2026-08-17  
状态：已确认，待实施计划

## 1. 目标

为 Obsidian Codex CLI 插件增加相互独立的工作区管理和写入白名单管理能力：

- 一个会话可以同时把多个本机目录作为项目工作区。
- 本机所有路径继续默认可读。
- 白名单只接受工作区内的现有文件或目录。
- 白名单内默认允许创建、修改、重命名和删除，不显示审批弹窗。
- 未命中白名单的写入继续显示“允许一次 / 拒绝”审批弹窗。
- 网络访问继续审批，Codex 原生网页搜索继续禁用。

插件首次启用或旧设置迁移后，工作区和白名单均为空，不自动扩大写权限。

## 2. 已确认的权限边界

| 位置与操作 | 默认行为 |
| --- | --- |
| 本机任意路径读取 | 允许 |
| 白名单内创建、修改、重命名、删除 | 允许，不弹窗 |
| 工作区内非白名单写入 | 弹窗审批 |
| 工作区外写入 | 弹窗审批 |
| 网络访问 | 弹窗审批 |
| Codex 原生网页搜索 | 禁用 |

该模型采用 Codex 原生权限档案。官方文档规定 `write` 同时包含创建、修改、重命名和删除，因此插件不会承诺对白名单内删除进行额外拦截：[OpenAI Codex Permissions](https://learn.chatgpt.com/docs/permissions)。

工作区外写入仍可通过逐次审批完成。这是保留全盘只读能力后的已确认取舍；插件不通过解析 PowerShell、Git 或复合命令来伪造更严格但无法可靠执行的路径边界。

## 3. 设置模型

插件设置新增两个字段：

```ts
interface CodexPluginSettings {
  codexPath: string;
  gitPath: string;
  workspaceRoots: string[];
  writablePaths: string[];
}
```

- `workspaceRoots` 保存用户明确添加的项目目录。
- `writablePaths` 保存默认可写的文件或目录。
- 两个字段默认均为 `[]`。
- 当前 Vault 继续作为 Codex 的 `cwd` 和内部运行根目录，但不会因此自动获得写权限。
- 保存设置沿用现有 `loadData` / `saveData`，旧设置通过默认值自然迁移。

## 4. 路径规则

工作区路径必须满足：

- 是 Windows 绝对路径。
- 路径存在且为目录。
- 解析后的真实路径可访问。

白名单路径必须满足：

- 是 Windows 绝对路径。
- 路径存在且为文件或目录。
- 解析后的真实路径位于某个工作区真实路径之内，或与工作区路径相同。
- 如需允许创建尚不存在的文件，应将其现有父目录加入白名单。

路径比较使用 Windows 语义：

- 不区分大小写。
- 统一目录分隔符并移除多余尾部分隔符。
- 解析 `.`、`..`、符号链接和目录联接。
- 使用路径相对关系判断包含关系，避免把 `D:\Project2` 误判为 `D:\Project` 的子目录。
- 重复的规范路径只保存一次。

移除仍包含白名单项的工作区时拒绝操作，并列出需要先移除的白名单项，避免静默改变权限含义。

## 5. 管理界面

插件设置页新增两个入口：

- “管理工作区”打开工作区管理弹窗。
- “管理写入白名单”打开白名单管理弹窗。

工作区管理弹窗提供：

- 当前工作区列表。
- 绝对路径输入和添加操作。
- 移除操作。
- 路径不存在、不是目录或重复时的就地错误提示。

白名单管理弹窗提供：

- 当前白名单列表及所属工作区。
- 文件或目录绝对路径输入和添加操作。
- 移除操作。
- 不属于工作区、路径不存在或重复时的就地错误提示。
- 明确警告：白名单内创建、修改、重命名和删除均不会弹窗。

第一版不增加路径拖拽、通配符、按会话切换的工作区集合或永久审批记录。

## 6. Codex 运行时配置

Codex 进程的 `cwd` 继续使用当前 Vault。线程新建、线程恢复和每次回合使用一致的工作区根列表：

```text
[当前 Vault, ...workspaceRoots]
```

列表按规范路径去重。权限档案保持：

```json
{
  "approvalPolicy": "on-request",
  "approvalsReviewer": "user",
  "permissions": "obsidian-vault",
  "config": {
    "web_search": "disabled",
    "permissions": {
      "obsidian-vault": {
        "filesystem": {
          ":root": "read",
          "<每个白名单真实路径>": "write"
        },
        "network": { "enabled": false }
      }
    }
  }
}
```

插件仅生成结构化权限配置，不分析命令字符串。未命中白名单的写入由 Codex 原生审批请求进入现有审批弹窗。

## 7. 配置生效与失败处理

- 保存工作区或白名单后，插件关闭当前 Codex 运行时。
- 下一次发送消息时，以新配置启动或恢复线程。
- 关闭运行时不会删除聊天记录或成果笔记。
- 启动运行时前重新校验所有工作区和白名单真实路径。
- 任一路径失效时拒绝启动并显示具体路径，不忽略失效项，也不扩大权限。
- 用户关闭管理弹窗而未保存时不改变现有设置。

## 8. 代码边界

预计改动集中在：

- `plugin/src/settings.ts`：设置字段、管理入口和设置持久化。
- `plugin/src/ui/modals.ts` 或独立管理弹窗模块：工作区与白名单界面。
- 新的路径策略模块：规范化、真实路径解析、包含关系和设置校验。
- `plugin/src/codex/codex-client.ts`：多工作区根和白名单权限配置。
- `plugin/src/main.ts`：把设置传入 Codex 运行时并在设置变化时关闭旧运行时。
- 对应单元测试、进程集成测试、README 和桌面验收文档。

不修改成果存储、Git 提交流程、聊天记录格式或现有审批按钮语义。

## 9. 测试与验收

自动测试必须覆盖：

- 新旧设置都得到空数组默认值。
- Windows 路径大小写、尾部分隔符、`.`、`..` 和相似目录名前缀。
- 符号链接和目录联接解析后不能绕过工作区校验。
- 工作区只能添加现有目录。
- 白名单只能添加工作区内的现有文件或目录。
- 移除含白名单项的工作区会被拒绝。
- 新建、恢复和每次回合传递同一组去重工作区根。
- 权限档案保持全盘只读，且只有白名单真实路径获得 `write`。
- 网络关闭、网页搜索禁用和人工审批策略保持不变。
- 设置变化会关闭旧运行时。

Windows 桌面验收必须覆盖：

- 两个不同目录可在同一会话中读取和检索。
- 白名单目录内创建、修改、重命名和删除不弹窗。
- 工作区内非白名单写入弹窗。
- 工作区外写入弹窗。
- 网络访问弹窗。
- 移除白名单并重启运行时后，同一路径写入恢复弹窗。
- 无效或失效路径显示明确错误且不启动会话。
